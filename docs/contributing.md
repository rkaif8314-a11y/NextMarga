# Contributing to NextMarga

## Before changing code

Read the relevant component or server route first and identify the smallest change that solves the problem.

## Pull requests

Use a focused branch and a descriptive commit message. Explain what changed, why it changed, and how it was verified. Avoid mixing unrelated refactors with feature work.

## Review checklist

- No secrets or generated artifacts are committed.
- Existing behavior is preserved unless the change intentionally modifies it.
- User-facing errors remain understandable.
- Responsive and keyboard behavior has been checked for UI changes.
- Build/test checks relevant to the change have been run.
